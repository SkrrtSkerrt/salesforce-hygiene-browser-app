Salesforce Hygiene Browser App

Public beta. Static, local-only ValidationRule XML check plus local report downloads. Your files stay in this browser tab. No uploads, no OAuth, no analytics.

No-upload MVP boundary

Your Salesforce metadata is processed in this browser tab. This public beta does not upload files, reports, or scan results to a server.

  • No Salesforce login.
  • No OAuth.
  • No analytics.
  • No server upload.
  • No scan-data persistence.

Try it: no Salesforce CLI needed

  1. Fast test: create a local file named Fictional.validationRule-meta.xml with the sample below, then select it here. You should see one blank-description finding.
  2. Real metadata without CLI: use a metadata ZIP or source folder you already have from an admin, release package, backup, or Git repo. Look for files ending in .validationRule-meta.xml.
  3. If you do not have metadata yet: ask your Salesforce admin or dev team for a small ZIP containing ValidationRule metadata only. This app cannot inspect an org by itself.
  4. Run the check: select a ZIP, folder, or individual XML files. The browser reads them locally and shows Limitations, Coverage rows, and Findings.
  5. Read the result: Not Assessed means the file was recognized but no current browser rule ran on it. Rejected means the file or ZIP entry was unsafe or unsupported.
  6. Save evidence: use Download JSON report or Download HTML report. The download is generated in this tab.
Fictional sample file for a 30-second test

Use this only as synthetic test data. Do not include credentials, org IDs, customer names, logs, screenshots, report content, filenames, or local paths in public feedback.

<ValidationRule xmlns="urn:metadata.tooling.soap.sforce.com">
  <fullName>Fictional_Blank_Description</fullName>
  <active>true</active>
  <description></description>
  <errorConditionFormula>ISBLANK(Name)</errorConditionFormula>
  <errorMessage>Name is required</errorMessage>
</ValidationRule>

Optional CLI users can retrieve metadata outside this app, then select the resulting local files or ZIP here. The page itself never logs in to Salesforce.
